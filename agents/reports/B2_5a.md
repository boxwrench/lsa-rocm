# B2.5a: KV offload and YaRN rope for very long dumps

Status: in progress (draft). Code written; GPU dumps pending (waiting for GPU 1 to idle).

## What was added to `src/lsa_rocm/dump.py`

### `--kv-offload` (requires `--prefill-chunk`, `--device cuda`)

Keeps the model's own full-attention K/V cache in CPU RAM between layer updates.
Two implementations, selected with `--kv-offload-impl`:

- `transformers` (default): `DynamicCache(config=config, offloading=True)`. transformers 5.16.1
  supports this natively: `Cache.update` prefetches the next offloaded layer on a side stream and
  offloads the layer it just updated. Linear-attention layers keep their recurrent state resident
  (`is_linear` layers are skipped by prefetch/offload). This is tried first.
- `custom`: a small wrapper `_OffloadingDynamicCache` around an ordinary `DynamicCache`. Its
  `update` copies the current layer's cached K/V to the computing device just before the update and
  back to CPU right after, so at most one full-attention layer's cache is on the GPU. It leaves
  `update_conv_state` / `update_recurrent_state` (linear attention) untouched. This exists as a
  fallback in case the transformers path misbehaves on the hybrid model, and uses a lower peak
  (one layer instead of two) at the cost of synchronous copies.

Our own K/V capture buffers remain CPU tensors, unchanged.

`meta.json` gains `kv_offload` (bool), `kv_offload_impl`, `kv_offload_moved_layers`.

### `--rope-yarn FACTOR`

Rewrites the loaded `AutoConfig` before the model is built:
`config.text_config.rope_parameters` gets `rope_type="yarn"`, `factor=FACTOR`,
`original_max_position_embeddings=<native max from the config>` (262144 for Ornith /
Qwen3.5-0.8B), preserving `rope_theta`, `partial_rotary_factor`, `mrope_section`,
`mrope_interleaved`; then `max_position_embeddings = native * factor`. The model is built from
that config, and the rope settings are read back from the built model
(`model...rope_emb.rope_type`, `attention_scaling`, `inv_freq`, and
`model.config.text_config`). A mismatch between the request and the readback aborts the run
rather than dumping a mis-scaled model.

`meta.json` gains `rope_scaling` with at least `rope_type`, `factor`,
`original_max_position_embeddings`, `max_position_embeddings`, `attention_scaling`, the request and
the full readback.

## Checks so far

- YaRN config path tested on CPU with Qwen3.5-0.8B (`--rope-yarn 4.0`, 512 tokens): built model
  reads back `rope_type=yarn`, `factor=4.0`, `max_position_embeddings=1048576`, YaRN
  `attention_scaling=1.138629436111989` (the expected mscale for factor 4). Self-check cosine
  1.00000012.
- `_OffloadingDynamicCache` exercised on CPU with fake K/V: concatenation, sequence length and
  offload-to-CPU work across two updates.
- Default behaviour is unchanged: the new flags default off, and the code paths are only taken when
  they are set.
