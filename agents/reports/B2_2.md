# B2.2 Block-sparse baseline control

## What was built

`src/lsa_rocm/baselines.py` (torch only, no new dependencies):

- `block_sparse_select(q, keys, pos, block_size, n_blocks, sink_size, window_size) -> (selected, lengths)`
  - Keys `[N, D]` raw (cast to float32), queries `[Nq, D]`, positions `[Nq]`.
  - Every **full/closed** block `b` of `block_size` consecutive keys (`b*block_size + block_size <= N`)
    is scored by `q . mean(keys[b*block_size:(b+1)*block_size])`. Only blocks that lie fully before
    the recent window (`b*block_size + block_size <= window_start`, i.e. `b < window_start // block_size`)
    and start at or after the sinks (`b*block_size >= sink_size`) are candidates.
  - Top `n_blocks` by mean-key dot product (ties to the lower block id), expanded to their keys, then
    the `window_size` most recent keys up to `pos` and the `sink_size` first keys are added.
  - Output: int32 `selected [Nq, S]`, `-1` padding, `lengths [Nq]` int32. Keys are distinct (a mask
    dedupes window/sink overlap and any overlap between them and the expanded blocks) and causal (`<= pos`).
    This is the same sink/window convention as `lsa_rocm.oracle.exhaustive_select`, so the baseline is
    directly comparable with the LSA selections under the same budget.
- `block_sparse_tree_select(..., coarse_factor=8, n_coarse=None)` — the two-level variant: coarse
  blocks of `block_size*8` keys are scored by their mean, the best `n_coarse` (default
  `ceil(n_blocks/coarse_factor)`) are refined at `block_size`, then the same sinks/window are added.
  Included because it was cheap (well under the 10-minute allowance).

## Tests

`tests/test_baselines.py` (unittest, CPU torch), all passing:

- planted-block recovery, flat and tree;
- sinks and window always present;
- causality (`<= pos`) and distinctness, including the degenerate positions 0/1;
- **exact set equality** against an explicit brute-force reference over several
  `(block_size, n_blocks, sink, window)` configurations, including `n_blocks=0`;
- output dtype/shape/padding;
- input validation;
- tree path equals the flat brute-force reference when the coarse level keeps every fine block.
